# Skeptic: Amen Shatter (W4-S2, Variant A first)
## TL;DR
- **BLOCKED: 0 BLOCKER, 3 HIGH, 4 MED, 4 LOW.** Variant A's shape holds: one pass, no FBO, a pure CPU core. Its cost margin holds, and so does the shatter frame's frame-mean luma. Every HIGH is a rule in the core, not in the GPU path, and each one has a Vitest that can falsify it.
- **A-1** K2 confirms a predicted shove on *any* broadband onset. 8th hats sit on both two-step kick slots, so the scene keeps "playing" a kick that has dropped out (C4, N1, C14).
- **A-2** `beat` can step backward (a `.` nudge; a same-tempo relock of ≤ ¼ beat). The mod-16 crossing rule then reads 1 slot back as 15 forward: a bar of moves and up to 15 stamps in one frame.
- **A-3** In autopilot, every real drop cuts the scene (`arrange.ts:73`, `app.ts:368`). The recipe can only run on a cold cut-in, and its first-frame rules are undefined there. S3 and the harness run with the scene held, so no gate before S7 sees this.
- MED: the layer clock again (the L-4 lesson); C12's fixed tile grid splits the disc; `barPhase` has no fit gate; the rise rule misses 16th-note re-triggers.

## §2 Checked and holding
- Contract: no change to `Native`, `NativeDef` or `FrameInput` (`gl/scene.ts:7`, `:13`; `frame.ts:7`). A lone normal generator on layer 0 draws straight into the RGBA8 shot target (`live.ts:348`), so Variant A is one pass.
- Rejecting Variant C holds: at 174 BPM a bar is 82.8 frames at 60 fps, and the ring holds 64 frames (32 slots × stride 2; design F3 L24, `history.ts:12`).
- Cost: take even the heaviest measured one-pass anchor (tiny-planet 2.40 ms, STATE). In a slow session (× 1.7) that is 4.1 ms, still ≤ 5. The post pass adds 2 fill-only blends after the scene's timer (`engine.ts:209–219`). Lever L4 (+55 % on move frames) would cut A's slow margin to ≈ 0.3 ms (1.8 × 1.55 × 1.7 = 4.7 ms), so pull it last.
- Per frame: 2 × 640-B `texSubImage2D` and ≈ 25 uniform vectors. There is no FBO, no readback and no stage-size resource, so tiles and governor scaling are safe. A lost context reloads the page (`engine.ts:17`).
- Clock domains: slots, beat crossings, the hold end and the histogram all read `f.sync.beat` (the audio clock), so heat cannot skew them. The gate counts on the app's `f.time` (`live.ts:329`).
- Hit labels: `slotOf` labels a hit from 8.6 ms before to 77.6 ms after its grid line at 174 BPM. That window absorbs the kick's +17…+29 ms post latency (dsp L97). The crossing comes 8.6 ms early, inside C10's ± 1 frame.
- Shatter-frame light (computed): the compose lights all 15 interior vertical lines × 10 rows, plus 3–4 horizontal seams per column: ≈ 22,800 px of seam. At ≈ 6.4 luma·px per px (the .35 halo cap; design L196's own figures), that is ≈ +.076 frame-mean, under C12's .10. The app flash has fallen to ≤ .06 by then (`post.ts:13`, τ = .1 s). On a tile, the seam light lands on the same frame as the ±4 relocation step, so it adds no extra C12 step.
- Moves conserve frame-mean luma to < 1 %: they permute whole cells, and the rows are 111 or 112 px (F4).
- Harness truth: `shatterState()` exposes the CPU truth for C4–C14. The lasers harness wraps `draw` in-page (`scratchpad/ed/s2.1-laser.mjs:64`), so the per-frame `moves` list stays in sync with the frames.
- Same-frame flash tie: binds run in the order of the `bind` object's keys (`live.ts:201`). So "`burst` first" means `burst` must be the first key, as in `lasers.ts:577`.
