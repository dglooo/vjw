# Skeptic challenge: donor-mode audio analyser (Tier 3 S2, recommended Variant A)

## TL;DR
- **BLOCKED:** 0 BLOCKER · 1 HIGH · 7 MEDIUM · 3 LOW (11 rows). **Recommendation: proceed with Variant A after the listed fixes.** Variants B and C carry the HIGH too, so it is no reason to switch.
- **C1 HIGH:** Variant A's rule "donor mode bypasses an override on a `syn_*` input" removes the I-FL1 fixes that 18 syn built-ins carry as overrides: SOFT_SNARE / SOFT_KICK attack .04 on 15 scenes, Deeper's attack .12, Beats in 4D's level attack .8, Canvas's BPMTri amount 0. A donor hit rises in one frame, so these scenes go back to their measured attack-0 luma-step counts (Alien Cavern 11, Dispersion 27, Deeper 5 in 1 s). Deeper lights the frame from HighHits with no ⚡ input, so R6 breaks as well. Fix: send the donor value through the input's own binding chain (dsp §C's source swap).
- **MEDIUM:** (C2) the silence → music edge fires all five band Hits at once and then mutes Hits for seconds; G1's clause does not fix this. (C3) H2 cannot see or fix the ungated classes. (C4) donor OnBeat fires about 3× as often as ours and fills the app-wide 3/s budget. (C5) G4 leaves out 120 / 144 Hz displays. (C6) T5 cannot fail. (C7) the `synValue` name guard is not tested against natives whose inputs are named like sources. (C8) the calibration scene grows 2.5× with no cost check.
- **Holding (§2):** R1 "no false drop", the R4 cost, persistence, flash-state survival, the raws' flash class, Library tiles. G2 is narrower than the design says (1 of 86 files).

## §2 Checked and holding
1. **R1, no false drop:** `arrangement.update` (`app.ts:348`) takes only low, high, total, kick, beat, cuts and now. The core runs after L348 and L383 and writes only `syn_*` keys and `donorMix`.
2. **No side effect at the switch:** `settings.onChange(sendConfig)` re-sends the worklet config only when `bandKey` changes (`app.ts:231–239`, `settings.ts:133–135`), and `analyser` is not part of the key.
3. **Persistence:** `parseSettings` (`settings.ts:49–63`) starts from the defaults and copies known fields. A missing or bad `analyser` reads 'ours', `v` stays 1, and no migration is needed. Only `patch()`'s Pick type (L88) needs the new field.
4. **Flash state across the switch:** Variant A rebinds nothing. Even on a rebind, `bindInto` keeps `state` and `flash` (`live.ts:253–255`).
5. **Crossfade vs the gate:** the same `FlashState` and `onsets` see one continuous value, and the ≤ 3/s cap holds for any input (`post.ts:46–58`). The gap is the shaping (C1), not the count.
6. **Raws' flash class:** donor Toggle, Random, BeatTime and Twitcher step on the same grid integer crossings as ours (`fx/syn.ts:74–77`; dsp §A1). The no-grid kick fallback keeps steps ≥ .25 s apart, so ≤ 2 rises/s, under 3/s.
7. **Count steps at the switch:** `seedBeat(floor(sync.beat))` makes the switch-in jump 0. The switch-out jump equals the divergence (kick-fallback steps, held re-anchors): one step (design A5), not a series.
8. **No Level is listed in any VJW_FLASH.** The 46 files list HighHits 29, BassHits 14, OnBeat 8, Hits 4, MidHighHits 2, MidHits 1 and BPMTri 1, so A4 has no current instance.
9. **G2 is narrower than A2 says:** only `redrum.glsl:332` tests `step(0.99, syn_HighHits)` (1 of 86 files). `thresholder.glsl:276` uses > .8 and `sun_set.glsl:98` uses > .5. G2 does not block S4, and C1's fix also applies SYN's ×1.35 / ×6 amounts to donor hits.
10. **A7 holds today:** grep finds no `name: 'syn_` outside `fx/syn`.
11. **−∞ dB does not poison the stats:** the prototype floors a band at −120 dB (`donor-model.ts:62`), `energy.update` does not mutate `magDb` (`energy.ts:44`), and `setAudio` clamps −∞ (`engine.ts:115`).
12. **Call site:** between `app.ts:406` and `:409`, the core sees this frame's grid (L383), arrangement (L348), kick (L324) and meter (L312). It runs before `sources()` and `gain()` (L414–415), so donor sources take the user's gain and mute. `sources()` writes no `syn_*` key, and `restyle` copies the donor keys to the built-ins (`bind.ts:87`).
13. **R4:** dsp §A3 measures p95 28.4–31.3 µs sequential and 29–69 µs contended (the score-v2 cost line shows p95 28.9–69.3 µs), against a 500 µs budget: ≥ 7× margin. The 512×1 RGBA upload is 2 KB, the same class as `setAudio`'s four uploads (`engine.ts:113–123`).
14. **Decision 2, Spectrum warm:** the juiced min / max snap to the current frame (`donor-model.ts:129–130`), so a gated cold start would cost ≈ 1 s of g-channel transient under the 2 s `_synMix` ramp. Warm costs < 31 µs. Either option holds; warm needs no branch.
15. **Library tiles:** `w` = 0 for an `own` instance (`live.ts:181–188`), which avoids baking a black FadeInOut frame.
16. **Context loss:** `engine.ts:17` reloads the page, so `audioTex.donor` needs no restore path (C10 covers the boot state).
17. **Per-frame allocation:** the prototype allocates on every frame (`donor-model.ts:93` Object.assign literal, the template keys at L122–124, `trail.set([…])` at L135). The contract (design L86) forbids this. It holds if the coder follows the contract; H3 should also report p99 and max.
18. **Variants B and C do not avoid C1:** B's DONOR_BIND (attack 0, release 0) replaces the overrides, and C shares A's read side. C1 is no reason to switch variant.
