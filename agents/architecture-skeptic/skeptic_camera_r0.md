# Architecture-skeptic challenge: camera R0-Mac ruling and the CP1 contract

## TL;DR
- **BLOCKED**: 0 BLOCKER, 1 HIGH, 9 MEDIUM, 2 LOW. The HIGH (K-1) closes with about 10 lines added to S1.2. It needs no re-design.
- K-1: the product path cannot recover from a failed or hung segmentation host. With ALIGN on, one `error` reply freezes the camera image and the mask until the next 30-min recycle.
- The ruling's top risk (live camera 18.9/91.9 ms) has no artifact. The only live run on disk (`fix-status.png`) reads 8.6/10.2 ms p50/p95. Downgrade it to MEDIUM. The cell that stays open is live camera × full-res HEAVY (K-2).
- The CP1 contract needs four rule changes before S1.2–S1.6: refcount on `setMask` (K-3), one reset path (K-4), `ref` as a texture (K-5), and a supersede guard in `selectCamera` (K-7).
- The picks hold: Selfie landscape, CPU, worker host, and the knob values.

**K-2, the gap's root-cause candidates in the code.**
- Frame size: not the cause. Clip and camera are both 1280×720 (gen-pattern.mjs L11, L `camSettings`). The worker gets the full frame.
- What `inferMs` measures: `createImageBitmap` (the resize) + the model + quantize + downsample (segment.worker.ts L236–L246).
- Frame storage: this does differ. The clip is software-decoded VP8 (CPU frames). The Mac camera most likely sends GPU-backed NV12 ⚠️ (unverified). Storage affects only the bitmap step.
- The hidden element and the rVFC cadence: neither can change `ms`, because the worker's clock starts when the message arrives.
- VideoFrame lifetime: at most 2 references per in-flight frame. The only leak path is terminate (K-6).
- Survival at ≥24 fps / ≤100 ms: yes, while the live p95 stays under 33.3 ms. No, at the 91.9 ms figure: ALIGN on makes every slow mask a 2–3-frame image stall.

## §1b Verdicts on the ruling's §7 risks
1. HIGH, live path unmeasured → **downgrade to MEDIUM** (K-2). The live run on disk reads 8.6/10.2 ms. The 91.9 figure has no artifact, and its status line counts every mask from start. What remains is live × full-res HEAVY, with ALIGN on as the amplifier.
2. HIGH, quality ungraded → **agree, HIGH** (the user accepted it). Cheapest detector before the booth clip: run one free 720p stock clip with one person (≥75 s) through W-selfie-cpu. This tests the person path end to end (area, presence, the gate's HOLD on entry, the edge). It cannot grade K6.
3. MEDIUM, K1/K3 not clean → **agree, MEDIUM; re-attribute**:
   - K1: the cause is likely the looping test clip, which has no Cues (K-8).
   - K3: grade the CP1 close against a same-session base, as ruling L460 does, not against plan L178's absolute "0 late".
   - The ALIGN-on split (3.8 against 1.2 late frames) comes from one sequential pass per arm, so it cannot rule ALIGN yet.
4. MEDIUM, PC unknown → **agree, MEDIUM**. Add: the PC run is also the first production-build run (K-10). Check the build on the M4 first.
5. LOW, RECYCLE/ALIGN on defaults → **agree, LOW** for the soak. The swap's teardown fails the CP1 hygiene line first (K-6).

## §2 Checked and holding
- Worker host over main: M-cpu reads 7.9 ms and M-same 14.1 ms `mainTotalP95` against K2 ≤2 ms (F). The pruned main host was never a viable PC fallback: it fails K2 by 4× on the faster M4.
- Selfie CPU speed: three independent windows agree: 10.1/11.2 (F), 9.6/10.8 (V) and 8.6/10.2 ms on the live camera (L).
- The GPU delegate gains nothing on the M4: 12.8/15.4 against 10.1/11.2 ms (F). Keeping only its init field for the PC costs nothing.
- The prune holds for RVM + ORT, multiclass (150.9 ms p50), deeplab (38.2 ms), Selfie square and Pose full. Each one can be restored from its named merge.
- The gate knobs in smooth.ts L11–L18 match the ruling table: AREA_MAX .6, JUMP .5 relative (L35), HOLD 6, SLOW .15, KEEP .85, PRESENCE_FULL .08.
- Main-thread cost on the live camera: upload 0.20 + mask side 0.30 ms p95 (L). K2 holds on the live path at that render load.
- Main-thread VideoFrame handling: every branch of `upload`, `onMask`, `black` and `stopModel` closes or transfers its frame (camera.ts L382–L436). Cloning before the transfer (L407) fixed the S0.4 "Cannot clone closed VideoFrame".
- `rvcGen` (L443–L458) and identity routing (`routeMsg`, L210–L215) hold: no double upload chains, and no masks dropped after a swap.
- GL state after the EMA pass: `render()` rebinds per scene and for the stage (engine.ts L203–L205). The probe ran this pass between HEAVY frames with no corruption.
- WebGL context loss reloads the page (engine.ts L17), so the camera textures need no restore path.
- Governor: `tick`'s JS time joins `jsMs`, but a step-down needs late frames (quality.ts L86). About 0.5 ms of JS alone changes nothing.
- Answers to the ruling's research gaps:
  - What `inferMs` covers: the bitmap resize + the model + the mask copy + quantize + downsample, without `stats` and the post (segment.worker.ts L236–L246).
  - The HEAVY scene: `builtin:td-feedback` (L status line: `heavy=builtin:td-feedback`).
  - `soak.recycle`: a swap count (camera.ts L51, L156).
  - PoseLandmarker lite size: 5,777,746 B. With Selfie, the total is 6.0 MB, inside the ≤10 MB budget.
