# Skeptic challenge: Rave Lasers (RL-S2, recommended Variant A)

## TL;DR
- **BLOCKED:** 0 BLOCKER · 1 HIGH · 6 MED · 4 LOW (11 rows).
- **L-1 HIGH:** rules 3 + 5 do not keep frame light flat for 1-beam emitters. One shared `flick` sends every n = 1 target `round(1 − 0.6·flick)` to 0 in the same step. W_MAX is used on purpose in the cage, so nothing compensates the loss. The build-peak cage (S3) blinks dark at 16ths, outside the flash gate.
- **Cost (L-2, L-3):** the basis adds a slow-session delta to a normal-session anchor and over-credits M1's fill. Corrected `full` drop: ≈ 2.8–3.6 ms normal, ≈ 4.7–5.8 ms slow (the design says ≤ 5.1). Expect L1 + L2 for `full`; `truss` holds (≈ 4.2–4.5 ms slow). No bench method holds the drop state yet.
- **Clock (L-4):** inside a native, `f.time` is the layer clock, scaled by heat and layer speed (`live.ts:244`), not wall clock. After a build, decision (a)'s 1-s window ends at 0.76–0.85 s real, before the two-step kick at 0.86 s.
- Holding: RGBA16F + per-frame `generateMipmap` (spec-valid, shipped in Isobars), the CPU rig, per-input gating, the max-channel hue argument, the `BLUR` export.

## §2 Checked and holding
- (2) RGBA16F + a per-frame `generateMipmap` is spec-valid. RGBA16F is texture-filterable in ES 3.0 core and colour-renderable with `EXT_color_buffer_float`; `generateMipmap` needs both (Khronos refpages). The engine uses RGBA16F only with the extension (`engine.ts:22`, `:81`). Isobars runs the same call every frame (`isobars.ts:499–500`), inside M2. ⚠️ Assumption: Chrome desktop exposes the extension. Without it the target falls back to RGBA8 and the HDR sum clamps.
- The mip state survives `fit()`: MIN_FILTER is set once on the same texture (`isobars.ts:343–344`), and `generateMipmap` rewrites the stale levels after a resize on the next frame.
- (5) The CPU rig is cheap: ≤ 256 × 12 floats = 12 KB per frame, against Isobars' 1.15 MB. It has no 96² field and no trace (they carry Isobars' 1.00–1.20 ms draw-CPU p95). It allocates 2 small objects per frame (`RigIn`, `RigOut`).
- (4) Light flatness holds in the uncapped regime (≥ 2 lit beams per emitter, W_MAX not binding): ≤ 1 beam per emitter per step, plus the global pin. The remainder is tone-map concavity (design risk 3), which C10's 8 % p95 measures. L-1 and L-7 are the exceptions.
- (3) The hue argument holds. A per-channel exp takes (0.1, 1, 0.38)·s to hue ≈ 156° at s·E = 3 (saturation 0.73), so C13 fails. The max-channel map keeps 138.7° exactly, also for green + white sums (white adds the same to every channel).
- Per-input gating works as the design says: only listed inputs pass `flashGate` (`live.ts:190`, `:304`), and an [F] bind must reach 0.5 to fire (`post.ts:34`, `:49`).
- Context loss reloads the page (`engine.ts:17`), so no per-native restore path is needed.
- (6) The `BLUR` export is the minimal reuse: one compiled program shared through the cache (`engine.ts:38–43`, `:61–64`) and no import cycle (lasers → isobars → engine). BLUR's σ and taps are fixed in the shader; Isobars' haze knobs live outside it.
- The sync and hats facts hold as stated: bpm 0 with no grid (`sync.ts:130`), LOCK 0.3 (`:33`), the 16-bar hold (`:28`, `:133`); hats = e^(−age / 0.06 s) × sens, capped at 1 (`features.ts:14`, `:110`).
- Out of scope by lead decision (d): per-beam chases at 5.8–11.6 Hz can flash 10° screen regions (WCAG 2.3.1 counts flash area per 10° field). R6 covers the full frame, and no check measures regions.
