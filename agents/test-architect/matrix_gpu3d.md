## §1 Strategy

**Layers and why.**
- `unit` (Vitest, pure seams, fake `gl` / fake WebGPU objects): counts, clamps, governor input, material flags, lifecycle state, growth policy, GL-state diff. Fast, runs on every merge.
- `contract`: build output (bundle split), bench JSON schema, asset licence manifest, R6 adapter precondition.
- `integration`: a Vitest or Node run over the real pipeline with fixtures (binding correlation).
- `browser` (Playwright-core on the host Chrome, as the S1-P / S1-W spikes): behaviour in the running app: lifecycle, loss, fallback, growth, cuts, recorder.
- `visual` (pixel checks on the composite; `scratchpad/ed/pxdiff.mjs` pattern): alpha, blend, fringe, fx-after, frozen pair.
- `performance` (billed p95 bench, A/B with the `own/flash` tail, slow-class label, 60 s runs at 1.00×).
- `manual`: the user's stills, the Windows PC bench. Owner = user.

**Test titles start with the matrix ID** (for example `P-U1 …`), so `npx vitest run … -t "P-U1"` filters one row.

**Harnesses (to write, base in brackets; the dispatch names the file).** Port 5176 as in S1-P / S1-T; a later step may take 5177.
- `scratchpad/gpu3d/g3-bench.mjs`: billed p95, points drawn, look, res, session class (base `s1p-bench.mjs`; the N* and 1 M records, splat rows A / B).
- `scratchpad/gpu3d/g3-60s.mjs`: 60 s run, late frames, `minScale` (base `cp4-60s.mjs`; also the crossfade run).
- `scratchpad/gpu3d/g3-cut.mjs`: 10 autopilot cuts (design § Particles rev 1, check).
- `scratchpad/gpu3d/g3-px.mjs`: pixel checks, blend and fringe, fx after (base `pxdiff.mjs`).
- `scratchpad/gpu3d/g3-webgpu.mjs`: marker lag, count conservation, saturation, `device.lost`, no `navigator.gpu` (base `s1w-stage2.mjs`).
- `scratchpad/gpu3d/g3-state.mjs`: GL-state diff, object counts, shader link, lifecycle, bundle requests (base `s1p-bench.mjs` + the S1-T instrument).
- `scratchpad/gpu3d/g3-rec.mjs`, `scratchpad/gpu3d/g3-cl.mjs`: recorder and context loss.

**Fixtures.**
- Audio: `scratchpad/fx_audio/dnb174-arr.wav` (live benches; drop at 34.1 s, as `DROP` in `s1p-bench.mjs`; break and bass-off section 23.07–34.10 s per the Serpent matrix), `scratchpad/fx_audio/dubstep140-arr.wav` (mono; Chrome reads [x, 0]). No isolated kick, snare or hat fixture exists: kick / hat behaviour of the fluid is checked with synthetic onsets in unit rows.
- Model: `donor/td-reverse/touchdesigner/extracted/Samples/glTF/Fox.glb` (read-only donor, S1-T spike only). It is a proxy for R3; the CC0 animal is not chosen (gap G4).
- Unit rows use pure inputs (no fixture file).

**Clock and seed.** `dt` clamped at 0.05 s (as the particle native). Synthetic onsets at 174 BPM, 60 fps, seeded PRNG. Particle seeding is GPU hash of `gl_VertexID` (deterministic); the pre-change CPU seed uses `Math.random` (not deterministic, see G1).

**Session class.** Every performance row runs alone (one Playwright Chrome) and reports the wireform+flash reference p95 in the same session. Slow class = reference p95 ≥ 3.33 ms (S1-P / S1-W precedent). Normal-class numbers are reported as such and never mixed with slow-class ones. An adapter that is not Apple `metal-3` gives UNKNOWN (row R6-PRE).

**UNKNOWN is never PASS.** A missing fixture, a missing dump, a missing WebGPU adapter or a missing record field gives UNKNOWN.

**What stays manual.** The user's stills review (creative gate, S3 and S7; M-V1), and the Windows PC bench (W-M1..W-M4). Technical calls stay with the lead.

**S1-T vs build.** S1-T rev 1 (lines 0–9) answers the three-library and model-state risks on the spike page. The build rows (P-, F-, M-, I-, L-) run after the planner's steps. Rows that repeat an S1-T line on the shipped demo are marked in `phase`.

**Gates.** `cd /Users/shaixee/Codered/Veejay-Wizard/web && npm run lint && npm run typecheck && npm test`, run by the lead after each merge (G-GATE).

## §4 Gaps and conflicts (lead rules)

- **G1. Frozen-pair bit-identical gate conflicts with C8 (project gate).** The gate says a frozen pair is bit-identical when an existing native gains inputs. `builtin:particles` gains `count`, and its seeding moves from CPU `Math.random` (`particles.ts` L103–L110) to a GPU hash (design § Particles rev 1 step 2). The first frame cannot be bit-identical to the pre-change build. Matrix replacement: P-R5-2 (KS, D ≤ 0.011) plus P-R5-1 (cost and luma within the run-to-run band). The lead must waive the bit-identical gate for this one native, or keep the CPU seed for the default count (this costs the C8 claim that create() fills no array).
- **G2. S1-W row B not measured.** `scratchpad/gpu3d/s1w.md` reports the bare row A (1 M 4.84 ms; res 0.5 3.89 ms) and the same-frame latency probe. It has no as-shipped look row (count-as-data, the particle look chain), and the 4.84 ms does not include the look. The design's own estimate for row B at res 1 is 5.8–7.1 ms plus atomics, so R1 via the splat path at res 1 is expected to miss. Needed: P-PERF3 and P-B5 before the splat path is claimed as R1.
- **G3. S1-T line 4 checks normal only.** The lead ruling N3 says line 4 checks each blend mode. S1-T's written line 4 does not. Matrix adds M-B2 (7 modes) for the build; the S1-T dispatch should add the 7-mode check to the running spike if it can be done in the same session, or the lead accepts M-B2 as the first build check.
- **G4. Assets.** The only GLB on disk is `donor/td-reverse/.../Fox.glb` (Khronos sample; licence not verified by test-architect, no internet). The spec's G3 says CC0 animal pack first; no animal is selected. R3 rows use Fox as a proxy. M-U6 (manifest) and M-V1 (user still on the real animal) close it. Donor assets need a plan step before copy (CLAUDE.md donor rule).
- **G5. No fluid spike or bench.** R2's cost line (≤ 4 ms in spec) rests on a computed estimate (1.8–2.9 ms). F-PERF1 is the first measurement. The lever (dye 512, pressure 12) is named in the design but no row tests it.
- **G6. Demo ids and bindings are not fixed.** The three built-in ids, their file paths and their audio bindings are not in the design. Test file paths in §2 are proposals. I-B4 (r ≥ 0.80) needs the binding list from the planner.
- **G7. Policies the design does not state.** P-B7 assumes a 16-bit saturate at 65535 (proposed). P-U3 assumes NaN → 65536 and round half up (proposed). M-U2 needs a rule for samples values outside {1, 4}. F-U4 needs the clamp constant. The planner names these; the tests then read them.
- **G8. Windows is manual only.** No automated check can measure the per-point cost on ANGLE D3D11. W-M1..W-M4 are the only Windows rows. R6 statement stays "stated, not measured" until the PC bench.
- **G9. S1-T line 9 scope.** S1T-9 covers existing scenes with three loaded. The particle and fluid natives (no `three`) need no R5 row beyond P-R5-1 and the bundle rows. Confirmed by design § Host rules; no gap.
- **G10. N* is not measured yet.** Bench N* (P-PERF1) decides the shipped count. Every row that names "the shipped count" depends on it. Until P-PERF1 reports, P-B2, P-B10 and I-GOV1 use 65 536 for the particle demo (stated in each row as the shipped count placeholder).
- **G11. Frozen-pair floor source.** S1T-2 and I-B1 use the design's "0.08/255 floor" (S1-T line 2). I did not verify where that figure comes from. The S1-T coder must cite it in the STATE entry before S1T-2 is used as a gate.
- **G12. Audio detector tests not added.** Kick / snare / hat discrimination, double hits and tempo change (SDLC §3 Stage 2 list) are not in scope: no detector change, so SDLC §4 is not triggered. The GPU3D layers only read existing `f.onsets` and energy. The fluid's hat and kick split is tested with synthetic onsets (F-U2, F-U3), and with `dnb174-arr.wav` in F-LAT.
- **G13. S1-T harness command names.** The S1-T dispatch names its file (not in `scratchpad/gpu3d/` yet). The `S1T-*` commands above are placeholders for that file.
